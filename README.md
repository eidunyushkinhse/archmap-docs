# Документация ArchMap (docs.archmap.tech)

Пользовательская документация [ArchMap](https://github.com/eidunyushkinhse/archmap): три
руководства — пользователя, архитектора и администратора. Исходники — Markdown в `content/`;
сайт собирает свой движок (`src/`, TypeScript, Node исполняет его напрямую); тема повторяет
стиль приложения (`theme/`), дерево страниц слева — дерево объектов продукта. Читателям сайт
открыт; автор входит по скрытому адресу и правит страницы в браузере, каждая правка — коммит
в этот репозиторий.

```bash
git clone https://github.com/eidunyushkinhse/archmap-docs.git && cd archmap-docs
npm ci
npm run hooks      # pre-commit-гейт: типы, тесты, сборка с проверкой ссылок
npm run password   # задать пароль автора (хэш — в .env)
npm run dev        # http://localhost:8800 — сервер, пересборка по правкам, перезагрузка вкладок
npm start          # то же без перезагрузки вкладок (для стенда)
npm run build      # dist/ как статика; битые ссылки и якоря останавливают сборку (CI)
npm run report     # карта фрагментов: какой текст на каких страницах
npm run check      # типы + тесты движка, авторизации, API и автокоммита
```

## Роли

- **Читатель** — любой посетитель: дерево страниц, поиск, чтение. Кнопок входа и правки
  на сайте нет.
- **Автор** — один пароль; вход по адресу `/login` (ссылок на него нигде нет, адрес набирается
  вручную). Сессия живёт 90 дней в cookie, поэтому с каждого устройства входят один раз.
  После входа в шапке появляются «Редактировать» и меню «Автор» (редактор, выход).
  Неверные попытки входа ограничены: 5 за 15 минут с адреса.

Пароль задаёт `npm run password` (пишет scrypt-хэш в `.env`); для локальной разработки можно
`DOCS_AUTHOR_PASSWORD=…` в `.env`. Ключ подписи сессий создаётся сам в `.data/session-secret`
(или `DOCS_SESSION_SECRET`). За nginx с TLS — `DOCS_TRUST_PROXY=true` (cookie Secure, адрес
клиента из X-Forwarded-For). Шаблон — `.env.example`.

## Редактор (`/edit/`)

Слева дерево страниц и фрагментов, справа поля (название, описание, порядок) и текст с
живым предпросмотром тем же движком, что собирает сайт. Вставки: фрагмент (строка
включения с правильным относительным путём), ссылка на страницу, блок, картинка (загрузка в
`content/images/`). Сохранение — <kbd>Ctrl</kbd>+<kbd>S</kbd>: файл пишется в `content/`,
сайт пересобирается, битые ссылки и якоря показываются под текстом. «+ Страница» создаёт
файл с фронтматтером (адрес — транслитерация названия, правится), «+ Фрагмент» — файл в
`_shared/`.

## Правки и git: автокоммит

Каждая правка через редактор (сохранение, новая страница, удаление, картинка) — отдельный
коммит в `content/`, который делает сам сервер: «Правка «Навигация» (user/navigation.md)»,
«Новая страница …», «Удалена страница …», «Картинка images/….png». Строка статуса под текстом
показывает хэш коммита. Правки файлов на диске мимо редактора сервер не коммитит — их
коммитит человек. Если папка не в рабочей копии git, автокоммит молча выключен; явно —
`DOCS_GIT_AUTOCOMMIT=false`.

Автор коммитов — `DOCS_GIT_NAME`/`DOCS_GIT_EMAIL`, иначе `git config` рабочей копии, иначе
«Автор документации <docs@archmap.tech>». Если подключён pre-commit-хук (`npm run hooks`),
автокоммит проходит через него: правка с битой ссылкой сохраняется на диск, но коммит не
проходит — редактор пишет «коммит не прошёл», следующий удачный сохранит всё.

На стенде включается отправка: `DOCS_GIT_PUSH=true` — каждый коммит сразу уходит в
`origin` (или `DOCS_GIT_REMOTE`), статус показывает «отправлено»; отклонённая отправка
(кто-то запушил с другого устройства) повторяется после `git pull --rebase`, а ошибка
остаётся в статусе и в `GET /api/git`. Серверу нужен ключ с правом записи — deploy key
репозитория (`ssh-keygen -t ed25519`, публичная часть — в Settings → Deploy keys с галкой
«Allow write access», remote по SSH). Чтобы на стенд попадали правки, сделанные в другом
месте, достаточно `git pull` в его рабочей копии: сервер пересобирает сайт по изменению файлов.

## Устройство content/

```
content/
├── index.md              главная («Домашняя страница» в дереве): заголовок и вводный текст
├── user/                 руководство = папка с index.md
│   ├── index.md          титульная: title, short (короткое имя), order, description
│   ├── navigation.md     страница: title, order, description
│   └── import/           подпапка = раздел навигации (заголовок — из её index.md)
├── architect/ …
├── admin/ …
├── _shared/              фрагменты для включений (страницами не становятся)
├── images/               картинки (копируются только те, на которые есть ссылки)
└── en/                   английская версия: та же структура (en/index.md, en/user/…, en/images/)
```

Адрес страницы — путь файла без `.md`: `user/navigation.md` → `/user/navigation/`,
`en/user/navigation.md` → `/en/user/navigation/` (см. «Английская версия» ниже).
Порядок в дереве — `order` во фронтматтере (меньше — выше), затем по названию.

## Фронтматтер

```md
---
title: Навигация по проекту
order: 1
description: Одной фразой — подзаголовок страницы, список разделов и поиск.
---
```

Если `title` нет, названием становится первый `# Заголовок` (он уходит из тела). Внутри тела
начинайте с `##`: `h1` — это название страницы.

## Единый источник истины: включения

Текст, нужный в нескольких руководствах, пишется один раз в `content/_shared/` и включается
строкой на отдельной строке:

```md
<!--@include: ../_shared/tree-navigation.md-->
```

Путь — относительно текущего файла (или от корня `content`, если начинается с `/`). Фрагмент
может включать другие фрагменты; цикл и отсутствующий файл — ошибка сборки. Ссылки и картинки
внутри фрагмента пишутся относительно **самого фрагмента**, а не страницы, куда он попадёт.
Якоря фрагмента (`{#tree}`) становятся якорями каждой страницы, куда он включён. В редакторе у
фрагмента видно, куда он включён; `npm run report` печатает ту же карту.

## Ссылки

- На страницу — относительным путём к её `.md`: `[Импорт](../architect/import.md)`.
- На раздел страницы — с якорем: `[Факты](../user/node-page.md#facts)`; внутри страницы — `[см. выше](#tree)`.
- Внешние (`https://…`) открываются в новой вкладке.

Сборка проверяет каждую ссылку: несуществующая страница или якорь — ошибка с подсказкой, какие
якоря есть. На фрагменты ссылаться нельзя — только на страницы, куда они включены.

## Якоря заголовков

Из текста: `## Дерево объектов` → `#дерево-объектов`. Устойчивый якорь, который переживёт
переименование заголовка, задаётся явно: `## Дерево объектов {#tree}`. Повтор якоря на одной
странице — ошибка.

## Картинки

```md
![Что на картинке](/images/depth-canvas.png "Подпись под картинкой")
```

Путь относительный или от корня `content` (с `/`); подпись (в кавычках) становится
`<figcaption>`. Файл должен существовать — иначе ошибка сборки.

## Формат инструкции

Страница руководства — не проза, а пошаговый путь от точки А до точки Б. Заголовок
страницы — целевое действие в инфинитиве («Найти проект и просмотреть устройство
системы»). Каждая процедура на странице:

```md
Чтобы <сделать X>, выполните следующие действия:

1. <Сделайте A>.
2. <Сделайте B>. <Появится M>.
3. <Сделайте C>.
```

У чистовой страницы нет `description`: подзаголовок под названием лишний, он остаётся только
у страниц-заглушек как подсказка автору и убирается, когда страница пишется.

Шаг — одно действие читателя и, если нужно, что он увидит в ответ. Всё, что не относится
к прямой пошаговой инструкции (устройство экрана, ограничения, когда чего-то нет, ссылки на
смежные разделы), оформляется блоками `::: note`, а не абзацами между шагами.

Порядок внутри шага: сначала ГДЕ, потом ЧТО, а конкретный жест, если нужен, отдельным
предложением «Для этого …»: «На странице сервиса в разделе **Схема** включите схему. Для этого
нажмите на неё». Не «Нажмите на схему, чтобы включить её». Оборот «…, чтобы …» в шагах не
используется.

Имена сущностей, экранов, кнопок, полей и пунктов меню — **жирным**, не в кавычках:
«нажмите кнопку **Легенда**», «поле **Поиск по имени**». Развилка из двух и более вариантов
или перечисление равноправных сущностей внутри шага — вложенным списком, а не через запятую:

```md
3. Подберите масштаб одним из способов:
    - колесом;
    - кнопками в левом нижнем углу схемы.
```

Не описывать элементы интерфейса ради описания: что видно на снимке или на экране, в тексте
не перечисляется («в карточке — название и число сообщений»). Примечание заслуживает только
то, что неочевидно: ограничение, когда чего-то нет, поведение, смежный раздел.

Длинное тире только там, где без него нельзя; сочетание «, —» запрещено совсем: перестроить
фразу (двоеточие, скобки, отдельное предложение).

Пример — в скобках с запятой после «например»: «событие (например, публикация сообщения в
брокер)», а не «событие, например публикация сообщения в брокер».

Без жаргона: не «хлебные крошки», а «путь от корня проекта вверху страницы»; не «дрилл», а
«спуститься на уровень ниже»; слова интерфейса — как в продукте. Содержимое контейнера — «компоненты», не «части». Блоки страницы проекта и
страницы объекта (**Схема**, **Связи**, **Логика**…) — «разделы»; «карточка» — только у проекта
на экране **Проекты**.

Отсылка к другому разделу — в скобках в конце предложения, а не через тире: «…откроется
выбранный процесс (см. [Просмотреть бизнес-процесс](processes.md)).»

Действие читателя не подаётся безличным глаголом во множественном числе или страдательным
оборотом («связи добавляют в редакторе», «в поле указывают топик», «проект наполняется в
редакторе»): так текст звучит назидательно. По смыслу — «можно сделать», «нужно сделать» или
«сделайте»: «Добавить связь можно в редакторе схемы», «в поле **Канал** укажите топик».
Безличная форма уместна только в описании: «Связь направлена от объекта, который обращается, к
объекту, к которому обращаются».

Указатель мыши — «курсор»: «наведите курсор на объект».

## Английская версия

Английские страницы лежат в `content/en/` с той же структурой, что у русских (`en/index.md`,
`en/user/…`, картинки — `en/images/`). Адреса — с префиксом `/en/`: `/user/levels/` ↔
`/en/user/levels/`; язык переключается в адресной строке, кнопки на сайте нет. У каждого языка
свои дерево, поиск, подписи сайта, кавычки (“…” вместо «…»), заголовки блоков (Note, Tip,
Warning, Caution) и страница 404. Ссылки между языками сборка не пропускает: английская
страница ссылается только на английские. Чего нет на английском, того нет в английском дереве.

Формулы — те же, что в «Формате инструкции», в английском виде:

| Русский | English |
|---|---|
| `Чтобы <сделать X>, выполните следующие действия:` | `To <do X>, follow these steps:` |
| `<Сделайте A>. <Появится M>.` | `<Do A>. <M appears>. / The <M> window opens.` |
| `… одним из способов:` | `… in one of the following ways:` |
| `Для этого …` | `To do this, …` |
| `(см. [Раздел](…))` | `(see [Section](…))` |
| `(например, …)` | `(for example, …)` |
| `можно … / нужно … / сделайте …` | `you can … / you need to … / do …` |
| `нажмите кнопку **X**` | `click **X**` |
| `наведите курсор на …` | `hover over …` |

Безличные и страдательные обороты о действиях читателя и в английском не используются:
«You can add relationships in the diagram editor», а не «Relationships are added in the editor».

## Блоки

```md
::: tip Заголовок по желанию
Совет.
:::
```

Виды: `note` (Примечание), `tip` (Совет), `warning` (Внимание), `danger` (Осторожно),
`details` — свёрнутый блок с заголовком-кнопкой. Клавиши — `<kbd>Ctrl</kbd>`. Код — обычными
блоками с языком (` ```bash `, ` ```yaml `): подсветка и кнопка «Копировать».

## Выкладка

Сервер (`npm start`) слушает 127.0.0.1:8800: перед ним nginx с TLS для docs.archmap.tech,
`DOCS_TRUST_PROXY=true`, автокоммит с отправкой — `DOCS_GIT_PUSH=true` (см. выше). Адреса
абсолютные от корня, поэтому сайт живёт на своём хосте; страница «не найдено» — `404.html`.
`dist/` после `npm run build` можно отдать и просто статикой — без авторского режима.
