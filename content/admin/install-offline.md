---
title: Установить ArchMap в закрытом контуре
order: 4
---

::: note
ArchMap не обращается во внешнюю сеть: после установки ему нужны только база PostgreSQL и пользователи. Доступ в интернет нужен один раз, чтобы получить поставку, а установить её можно на сервер или в кластер без интернета. Для закрытого контура подходят установка на сервер и установка в Kubernetes. Docker Compose собирает образ из исходного кода и без интернета не работает.
:::

## Установить на сервер без интернета

Чтобы установить ArchMap на сервер без доступа в интернет, выполните следующие действия:

1. На машине с доступом в интернет соберите архив поставки (см. [Собрать архив поставки](install-server.md#собрать-архив-поставки)).
2. Перенесите архив и файл `.sha256` в закрытый контур способом, принятым в вашей организации.
3. Установите ArchMap из архива (см. [Установить ArchMap](install-server.md#установить-archmap)).

::: note
Все зависимости уже лежат в архиве поставки: переносной Python, пакеты бэкенда и собранный интерфейс. Пакеты бэкенда ставятся при сборке строго по файлу `backend/requirements-prod.lock` с контрольными суммами, поэтому в поставку попадают ровно те версии, что указаны в репозитории.
:::

## Перенести образ и чарт в свой реестр

Чтобы установить ArchMap в кластер без доступа в интернет, выполните следующие действия:

1. На машине с доступом в интернет сохраните образ ArchMap нужной версии в файл (например, с помощью skopeo):

    ```bash
    skopeo copy --all docker://ghcr.io/eidunyushkinhse/archmap:ВЕРСИЯ \
      oci-archive:archmap-ВЕРСИЯ.tar
    ```

2. Скачайте архив чарта той же версии:

    ```bash
    helm pull oci://ghcr.io/eidunyushkinhse/charts/archmap --version ВЕРСИЯ
    ```

3. Перенесите файлы `archmap-ВЕРСИЯ.tar` и `archmap-ВЕРСИЯ.tgz` в закрытый контур.
4. Загрузите образ в реестр закрытого контура:

    ```bash
    skopeo copy --all oci-archive:archmap-ВЕРСИЯ.tar \
      docker://registry.example.com/archmap:ВЕРСИЯ
    ```

5. Добавьте в файл значений `archmap-values.yaml` адрес образа в своём реестре:

    ```yaml
    image:
      repository: registry.example.com/archmap
      tag: ВЕРСИЯ
    ```

6. Установите чарт из архива (см. [Установить чарт](install-kubernetes.md#установить-чарт)), указав вместо `oci://…` путь к файлу:

    ```bash
    helm install archmap ./archmap-ВЕРСИЯ.tgz -n archmap -f archmap-values.yaml --wait
    ```

::: note
Образ можно собрать и самостоятельно из исходного кода: `docker build -t registry.example.com/archmap:ВЕРСИЯ .` в корне репозитория, затем `docker push`. Если реестр требует авторизации, укажите Secret для загрузки образа в значении `imagePullSecrets`.
:::

## Подключить ИИ-агентов при внутреннем центре сертификации

::: note
Если сертификат ArchMap выпущен внутренним центром сертификации, ИИ-агенты пользователей должны доверять этому центру, иначе они не подключатся по MCP.
:::

Чтобы ИИ-агенты пользователей подключались к ArchMap, выполните следующие действия:

1. Определите файл корневых сертификатов, в который на компьютерах пользователей установлен ваш центр сертификации (обычно `/etc/ssl/certs/ca-certificates.crt` в Debian, Ubuntu и Astra Linux или `/etc/pki/tls/certs/ca-bundle.crt` в RHEL и родственных системах).
2. Сообщите пользователям путь к этому файлу и переменную окружения, в которой его нужно указать:
    - для агента на Node.js (например, Claude Code или Qwen Code) `NODE_EXTRA_CA_CERTS`;
    - для локального MCP-сервера ArchMap `SSL_CERT_FILE`.
3. Если доступ в сеть идёт через прокси, попросите пользователей внести адрес ArchMap в переменную `NO_PROXY` (см. [Подключить ИИ-агента к ArchMap](../user/agent-setup.md)).

::: note
Документировать код с помощью ИИ-агента можно теми агентами, которые разрешены в вашем контуре: агент подключается к ArchMap по адресу `…/mcp` или работает с промптами из окон ArchMap.
:::
