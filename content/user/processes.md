::: note
Бизнес-процесс показывает по шагам, как сервисы взаимодействуют в одном сценарии (например, при оплате заказа): кто кого вызывает, что отвечает и какие события публикует. Процесс изображён диаграммой последовательности: участники стоят сверху, шаги идут сверху вниз.
:::

## Открыть процесс

Чтобы открыть бизнес-процесс, выполните следующие действия:

1. Откройте проект (см. [Найти проект и просмотреть устройство системы](find-project.md)).
2. В шапке нажмите **Процессы**. Слева откроется список процессов проекта.
3. В списке нажмите на нужный процесс. Справа появится его диаграмма.

![Бизнес-процесс](../images/process-view.png "Процесс «Оплата заказа»: список процессов слева, участники сверху, шаги по порядку номеров")

::: note
Процесс можно открыть и с других страниц:
- на странице проекта или сервиса в разделе **Процессы**;
- в окне схемы логики в строке **В процессах:**.

К схеме системы возвращает вкладка **Объекты** в шапке.
:::

## Прочитать диаграмму

Чтобы прочитать диаграмму процесса, выполните следующие действия:

1. Пройдите по шагам в порядке номеров. Вид стрелки показывает тип шага:
    - сплошная линия и закрашенный наконечник: вызов;
    - пунктирная линия: ответ на вызов;
    - сплошная линия и открытый наконечник: событие (например, публикация сообщения в брокер).
2. Нажмите на подпись нужного шага. Справа появятся его участники, тип, технология и схема логики.
3. На диаграмме откройте схему логики шага. Для этого нажмите значок после его подписи. Откроется окно со схемой логики операции, которая выполняет шаг (см. [Просмотреть логику операции или воркера](logic.md)).
4. Над диаграммой откройте страницу нужного участника. Для этого наведите курсор на его имя и нажмите на появившуюся стрелку. Откроется страница объекта.

::: note
Если значка после подписи нет, к шагу не привязана схема логики.
:::

::: note
Рамка с меткой в левом верхнем углу объединяет шаги, которые выполняются по особому правилу:
- **alt**: выполняется одна из веток, условие каждой ветки подписано в рамке;
- **opt**: шаги выполняются, только если выполнено условие;
- **loop**: шаги повторяются;
- **par**: шаги выполняются параллельно.
:::

::: note
Зачёркнутый шаг расходится со схемой системы, а пометка рядом называет причину:
- **связь удалена**: связи, по которой шёл шаг, больше нет;
- **связь без ответа**: шаг описывает ответ, а связь стала асинхронной и ответа не предполагает.
:::

::: note
Если процесс описан в пределах части системы, её имя видно в подсказке при наведении курсора на название процесса.
:::
