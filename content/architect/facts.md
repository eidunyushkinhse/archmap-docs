::: note
Факты — табличная часть документации: структура базы данных (раздел **Структура** на странице базы данных), каналы брокера сообщений (раздел **Каналы** на странице брокера) и параметры конфигурации (раздел **Конфигурация** на странице сервиса). Факты можно править прямо в разделе страницы: изменение сохраняется, когда вы уходите из поля.
:::

::: note
Описать факты можно и силами агента: он прочитает миграции, код и конфиги репозитория (см. [Импортировать схемы логики, точки входа и факты от агента](docs-import.md#описать-структуру-бд-каналы-и-конфигурацию)).
:::

## Описать таблицу базы данных

Чтобы описать таблицу, выполните следующие действия:

1. На странице базы данных в разделе **Структура** нажмите **+ Таблица** и выберите **Вручную**. Появится новая таблица.
2. Введите имя таблицы и коротко опишите её назначение.
3. Если у базы есть разделы (например, схемы в PostgreSQL), укажите раздел таблицы.
4. Нажмите **+ Колонка** и заполните колонку:
    - имя и тип;
    - флажки **ключ** (первичный ключ) и **обяз.** (значение обязательно);
    - в списке **Ссылается на** колонку, на которую ссылается внешний ключ;
    - смысл значения.
5. Повторите предыдущий шаг для остальных колонок.

::: note
Кнопки удаления таблицы и колонки находятся справа от их строк. Связи между таблицами по внешним ключам показывает ER-диаграмма (кнопка **Показать диаграмму** в разделе **Структура**).
:::

## Описать канал брокера

Чтобы описать канал, выполните следующие действия:

1. На странице брокера в разделе **Каналы** нажмите **+ Канал** и выберите **Вручную**. Появится новый канал.
2. Введите имя канала так же, как оно записано в коде (например, `orders.events`), и коротко опишите его назначение.
3. Укажите вид канала (например, `topic` в Kafka, `queue` или `exchange` в RabbitMQ).
4. Если нужно, заполните параметры доставки:
    - ключ партиционирования;
    - гарантию доставки (например, `at-least-once`);
    - срок хранения сообщений (например, `7d`).
5. Нажмите **+ Поле** и опишите поле сообщения: имя, тип, обязательность и смысл значения.
6. Повторите предыдущий шаг для остальных полей.

::: note
Если у брокера каналы разбиты на группы (vhost в RabbitMQ, namespace в Pulsar), укажите группу канала. У Kafka такого уровня нет, поэтому для неё оставьте поле пустым.
:::

## Описать параметр конфигурации

Чтобы описать параметр, выполните следующие действия:

1. На странице сервиса в разделе **Конфигурация** нажмите **+ Параметр** и выберите **Вручную**. Появится новый параметр.
2. Введите имя параметра так же, как оно записано в коде (например, `MAX_ITEMS_PER_ORDER`).
3. Укажите тип значения (например, `int`, `bool`, `duration`).
4. Если без параметра сервис не запустится, установите флажок **обяз.**.
5. Укажите значение по умолчанию из кода.
6. Опишите, что переключает параметр.

::: note
ArchMap хранит только значение параметра по умолчанию из кода. Значений для конкретных сред (тестовой, боевой) в нём нет. Не записывайте в документацию пароли, токены и другие секреты.
:::

::: note
Параметр принадлежит сервису. Если одинаковый параметр есть у двух сервисов, опишите его у каждого, потому что назначение и значение по умолчанию у них могут отличаться.
:::

::: note
Строки **Кто обращается** у таблицы, **Кто публикует / кто потребляет** у канала и **зависит:** у параметра ArchMap строит сам по пометкам в схемах логики: `читает:`, `пишет:`, `публикует:`, `потребляет:` и `зависит от:`. Чтобы факт появился в этих строках, добавьте пометку в шаг схемы, который к нему обращается (см. [Написать схему логики операции или воркера](logic.md#markers)).
:::
