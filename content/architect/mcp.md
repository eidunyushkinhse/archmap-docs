::: note
ИИ-агент, подключённый к ArchMap по MCP, не только отвечает на вопросы по документации, но и пишет её сам: строит схему по коду, обновляет её, задаёт тип объектов, описывает схемы логики, структуру баз данных, каналы и конфигурацию, переносит документацию к объектам, которым она принадлежит, привязывает шаги процессов, размещает объекты по площадкам, а по явной просьбе ставит статус страницы и фиксирует версию документации. Переносить YAML и пакеты от агента в окна ArchMap вручную не нужно. Как подключить агента, см. [Подключить ИИ-агента к ArchMap](../user/agent-setup.md).
:::

## Поручить агенту документирование

Чтобы агент изменил документацию в ArchMap, выполните следующие действия:

1. Подключите агента с токеном без флажка **Только чтение** (см. [Подключить ИИ-агента к ArchMap](../user/agent-setup.md)).
2. Запустите агента в папке репозитория системы.
3. Опишите задачу своими словами и назовите проект. Например:
    - «Построй схему системы по этому репозиторию и создай проект «Ярмарка»»;
    - «Обнови схему проекта «Ярмарка» по свежему коду»;
    - «Опиши логику операций Catalog API в проекте «Ярмарка»»;
    - «Опиши структуру БД каталога в проекте «Ярмарка»»;
    - «Поставь Order API в проекте «Ярмарка» на площадки «Кластер prod» и «Кластер резерв»»;
    - «Перенеси документацию системы «Ярмарка» в её контейнеры и компоненты».
4. Просмотрите план изменений, который покажет агент. В плане перечислено, что будет создано, изменено или помечено устаревшим.
5. Подтвердите план. Агент запишет изменения в проект.
6. Проверьте результат в ArchMap и разберите рекомендации, если они появились (см. [Разобрать рекомендации к схеме](alerts.md)).

::: note
Перед любой записью агент получает от ArchMap план изменений и только потом применяет его. Если агент не показал план, попросите показать его перед применением. Если ArchMap не принимает файл агента (например, у объекта с вложенными объектами не указан тип), агент вместо плана получает отказ с причиной и исправляет файл сам.
:::

::: note
Агенту виден тип каждого объекта: в дереве схемы и в карточке объекта, а размещение и статус страницы в карточке показаны так же, как в интерфейсе (у компонента площадки его контейнера, у системы статус из вложенных объектов). Агент задаёт тип при создании объекта и может сменить его. Смена типа переносит площадки так же, как в интерфейсе, а документацию оставляет на месте.
:::

::: note
Документацию, которая оказалась не у того объекта, агент переносит так же, как кнопки **Перенести документацию** и **Собрать с компонентов**: сначала показывает, что куда перейдёт, и записывает после подтверждения (см. [Разобрать рекомендации к схеме](alerts.md)). Когда агент создаёт проект из нескольких файлов или догружает архивы, он видит те же вопросы, что окно ввоза задаёт человеку, и передаёт ваши ответы (см. [Ответить на вопросы слияния](merge-repos.md#questions)).
:::

::: note
Правила оформления агент берёт у самого ArchMap: это те же промпты, что выдают окна **Новый проект**, **Обновить из репозитория** и окна описания логики и фактов. Поэтому результат получается таким же, как при переносе файлов вручную (см. [Импортировать схему, собранную агентом из кода](import-agent.md), [Документировать систему с помощью ИИ-агента](agent-docs.md)).
:::

::: note
Агент правит только проекты, где вы владелец или редактор, а создать новый проект может, только если у вас общая роль «Архитектор». Удалять объекты агент не может: то, что пропало из кода, он помечает статусом **Выводится**, а удалить такие объекты можно кнопкой **Принять переход** (см. [Описать планируемые изменения системы](changes.md)). Единственное, что агент стирает, это повторы при сборе с компонентов: как и кнопка **Собрать с компонентов**, сбор удаляет одноимённые параметры и спецификации компонентов, если у контейнера есть свои или вы выбрали одно описание из нескольких (см. [Собрать конфигурацию с компонентов](config.md#collect)). Управлять проектом и его участниками агент тоже не может. Площадки агент не создаёт, а размещает объекты только на заведённых в интерфейсе (см. [Разместить объекты по площадкам](deployment.md)); вернуть документацию к прежней версии агент тоже не может, это делает редактор на странице объекта (см. [Зафиксировать версию документации и вернуться к ней](versions.md)).
:::

::: note
Агенту доступны те же рекомендации, которые показывает панель **Рекомендации**. Можно попросить его найти и исправить пробелы (например, «найди в проекте «Ярмарка» обращения к неописанным таблицам и опиши их»).
:::

## Подключить локальный MCP-сервер для архивов

::: note
Агенту, подключённому по адресу, недоступен диск: скачать архив проекта, создать проект из архива или догрузить архив в проект он не может. Для таких задач подключите локальный MCP-сервер ArchMap: он работает на компьютере агента и читает и пишет архивы на его диске. В остальном он работает так же, как сервер по адресу.
:::

Чтобы подключить локальный MCP-сервер, выполните следующие действия:

1. Убедитесь, что на компьютере установлены Python 3.11 или новее и git.
2. Скачайте исходный код ArchMap и установите MCP-сервер:

    ```bash
    git clone https://github.com/eidunyushkinhse/archmap.git
    cd archmap/mcp
    python3 -m venv venv
    ./venv/bin/pip install -r requirements.txt
    ```

3. Создайте файл настроек `mcp/.env` из шаблона:

    ```bash
    cp .env.example .env
    ```

4. В файле `mcp/.env` укажите адрес ArchMap и токен (см. [Выпустить токен](../user/agent-setup.md#выпустить-токен)):

    ```bash
    ARCHMAP_URL=https://archmap.example.com
    ARCHMAP_TOKEN=archmap_...
    ```

5. Добавьте сервер в файл настроек MCP-серверов агента, указав полный путь к папке `mcp`:

    ```json
    {
      "mcpServers": {
        "archmap": {
          "command": "/полный/путь/archmap/mcp/venv/bin/python",
          "args": ["-m", "archmap_mcp.server"],
          "env": {
            "PYTHONPATH": "/полный/путь/archmap/mcp"
          }
        }
      }
    }
    ```

6. Перезапустите агента и попросите его показать список проектов ArchMap.

::: note
Токен храните только в файле `mcp/.env`, потому что этот файл не попадает в git. В файл настроек агента токен не вписывайте, если этот файл лежит в репозитории.
:::

::: note
Если ArchMap открывается по HTTPS с сертификатом внутреннего центра сертификации, укажите файл корневых сертификатов в переменной `SSL_CERT_FILE` в блоке `env` настроек агента (например, `/etc/ssl/certs/ca-certificates.crt`).
:::

::: note
Чтобы агент сохранял архивы только в одной папке, укажите её в `mcp/.env` в переменной `ARCHMAP_EXPORT_DIR` (например, `ARCHMAP_EXPORT_DIR=~/archmap-exports`).
:::
