---
title: Импортировать схемы логики, точки входа и факты от агента

---

::: note
Когда схема системы готова, ИИ-агент может дописать документацию каждого объекта: схемы логики операций и воркеров, список точек входа, структуру базы данных, каналы брокера и параметры конфигурации. Все такие окна устроены одинаково: окно на странице объекта выдаёт промпт, вы запускаете агента в репозитории сервиса, агент складывает файлы в папку `archmap-docs/` репозитория, а вы загружаете их в то же окно, проверяете и применяете.
:::

::: note
Промпт рассчитан на агента, который умеет запускать субагентов: один субагент пишет документацию, второй проверяет её по коду. Если агент субагентов не поддерживает, он остановится и сообщит об этом.
:::

## Описать логику сервиса

Чтобы получить схемы логики от агента, выполните следующие действия:

1. На странице сервиса в разделе **Логика** нажмите **+ Добавить** и выберите **Через ИИ-агента**. Откроется окно **Описать логику с помощью агента**.
2. Выберите режим:
    - **Пакетом**: агент опишет все операции и воркеры сервиса за один заход. Подходит для небольших сервисов;
    - **По одной схеме**: агент опишет одну операцию или один воркер. Подходит для крупных монолитов. В поле **Что описать** укажите воркер или эндпоинт (например, `POST /orders`).
3. В поле **Язык подписей** выберите язык, на котором агент подпишет шаги схем.
4. Если нужно, в поле **Подсказки агенту** уточните задание (например, «документируй только сервис billing»).
5. Нажмите кнопку **Скопировать промпт**.
6. Запустите агента в папке репозитория сервиса, вставьте промпт и отправьте. Агент сложит файлы схем в папку `archmap-docs/` репозитория.
7. В окне перетащите файлы из папки `archmap-docs/` в поле справа. Под полем появится проверка: какие схемы будут созданы или обновлены.
8. Если нужно, поправьте в проверке имя или вид схемы.
9. Нажмите кнопку **Применить** (в режиме **По одной схеме** — **Добавить**). Схемы появятся в разделе **Логика**.

::: note
По умолчанию схема с тем же именем, что уже описана в ArchMap, не перезаписывается. Чтобы заменить готовые схемы новыми, установите флажок **Обновлять готовые диаграммы** перед применением.
:::

::: note
В режиме **По одной схеме** кнопка **Добавить ещё** применяет схему и оставляет окно открытым для следующей операции.
:::

::: note
Если проверка нашла замечания (например, пометка ссылается на таблицу, которой нет в документации), нажмите **Скопировать замечания для агента** и отправьте текст агенту в ту же сессию. Агент исправит файлы: загрузите их в окно заново.
:::

::: note
Описать или переписать одну схему можно и прямо в её окне: в шапке окна нажмите **Изменить** и выберите **Через ИИ-агента**.
:::

## Составить список операций

::: note
В крупном сервисе десятки и сотни операций, и описать их все одним заходом агент не успеет. Сначала соберите их список: ArchMap создаст по каждой операции пустую схему-заглушку, и их можно будет описывать по одной.
:::

Чтобы составить список операций, выполните следующие действия:

1. На странице сервиса в разделе **Логика** нажмите **+ Добавить** и выберите **Составить список операций**. Откроется окно **Составить список операций с помощью ИИ-агента**.
2. Нажмите кнопку **Скопировать промпт**.
3. Запустите агента в папке репозитория сервиса, вставьте промпт и отправьте. Агент положит файл `archmap-recon.yaml` в корень репозитория.
4. В окне перетащите файл `archmap-recon.yaml` в поле справа. Под полем появится проверка: какие заглушки будут созданы.
5. Нажмите кнопку **Применить**. Заглушки появятся в блоке **Не описано** в разделе **Логика**.

::: note
Список ничего не удаляет и не перезаписывает. Схема, которая уже описана, остаётся как есть. Схема, которой агент не нашёл в коде, попадает в группу **Есть в документации, но не найдено в коде**: удалить её можно вручную, если она действительно устарела.
:::

::: note
Список можно собирать повторно: новых заглушек появится ровно столько, сколько в коде появилось новых операций.
:::

## Описать операцию из списка

Чтобы описать операцию-заглушку, выполните следующие действия:

1. На странице сервиса в разделе **Логика** раскройте блок **Не описано** и нажмите на операцию. Откроется окно с надписью **Эта операция ещё не описана**.
2. Нажмите **Описать** и выберите **Через ИИ-агента**. Промпт в окне уже настроен на эту операцию.
3. Скопируйте промпт, запустите агента в репозитории сервиса и загрузите полученный файл в окно.
4. Нажмите кнопку **Применить**. Заглушка заполнится, и операция переедет из блока **Не описано** в список **Операции**.

## Описать структуру БД, каналы и конфигурацию

Чтобы получить факты от агента, выполните следующие действия:

1. Откройте страницу объекта и нажмите кнопку добавления в нужном разделе:
    - для базы данных: в разделе **Структура** кнопку **+ Таблица**;
    - для брокера сообщений: в разделе **Каналы** кнопку **+ Канал**;
    - для сервиса: в разделе **Конфигурация** кнопку **+ Параметр**.
2. В меню выберите **Через ИИ-агента**. Откроется окно агента.
3. Нажмите кнопку **Скопировать промпт**.
4. Запустите агента в папке репозитория, вставьте промпт и отправьте. Агент сложит файлы в папку `archmap-docs/` репозитория.
5. В окне перетащите файлы из папки `archmap-docs/` в поле справа. Под полем появится проверка: какие таблицы, каналы или параметры будут записаны.
6. Нажмите кнопку **Применить**.

::: note
По умолчанию то, что уже описано, не меняется: агент только добавляет недостающее. Чтобы новые описания заменили старые, установите флажок **Перезаписывать заполненное**. Удалений нет ни при какой настройке.
:::

::: note
Таблицы, каналы и параметры связываются со схемами логики через пометки «читает», «пишет», «публикует», «потребляет» и «зависит от» (см. [Написать схему логики операции или воркера](logic.md)). Поэтому структуру БД и каналы удобнее описать до схем логики: тогда агент будет ссылаться в схемах на уже известные имена.
:::

::: note
Значения параметров для конкретных сред (тестовой, боевой) ArchMap не хранит: агент записывает только значение по умолчанию из кода.
:::
