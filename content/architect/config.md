::: note
Параметры [конфигурации](../glossary.md#config) (переменные окружения, флаги, настройки) описывайте в разделе **Конфигурация** на странице [контейнера](../glossary.md#container). Правки в разделе сохраняются, когда вы уходите из поля.
:::

::: note
ArchMap хранит только значение параметра по умолчанию из кода. Значений для конкретных сред (тестовой, боевой) в нём нет. Не записывайте в документацию пароли, токены и другие секреты.
:::

## Описать параметр вручную {#param}

Чтобы описать параметр, выполните следующие действия:

1. На странице контейнера в разделе **Конфигурация** нажмите **+ Параметр** и выберите **Вручную**. Появится новый параметр.
2. Введите имя параметра так же, как оно записано в коде (например, `MAX_ITEMS_PER_ORDER`).
3. Укажите тип значения (например, `int`, `bool`, `duration`).
4. Если без параметра приложение не запустится, установите флажок **обяз.**.
5. Укажите значение по умолчанию из кода.
6. Опишите, что переключает параметр.

::: note
Параметр принадлежит контейнеру. Если одинаковый параметр есть у двух контейнеров, опишите его у каждого, потому что назначение и значение по умолчанию у них могут отличаться.
:::

::: note
Строку **зависит:** у параметра ArchMap строит сам по пометкам `зависит от:` в шагах схем логики контейнера и его компонентов (см. [Сослаться на таблицы, каналы и параметры](logic.md#markers)).
:::

## Описать конфигурацию с помощью ИИ-агента {#agent}

<!--@include: ../_shared/agent-beta.md-->

::: note
Агент ищет все места, где код сервиса читает конфигурацию: переменные окружения, классы настроек, флаги командной строки. Перечень он дополняет объявлениями из `.env.example`, docker-compose, Helm-чартов и манифестов Kubernetes. Назначение параметра агент описывает по тому, что параметр меняет в коде. Значения параметров он не переносит: из файлов с секретами (например, `.env` или Secret в Kubernetes) берёт только имена, а значение по умолчанию записывает, только если оно задано в коде.
:::

Чтобы описать конфигурацию сервиса с помощью агента, выполните следующие действия:

1. На странице контейнера в разделе **Конфигурация** нажмите **+ Параметр** и выберите **Через ИИ-агента**. Откроется окно **Описать конфигурацию с помощью ИИ-агента**.
2. Нажмите кнопку **Скопировать промпт**.
3. Запустите агента в папке репозитория, вставьте промпт и отправьте. Агент сложит файлы в папку `archmap-docs/` репозитория.
4. Добавьте файлы из папки `archmap-docs/` в окно одним из способов:
    - перетащите файлы в поле справа;
    - нажмите **Загрузить файлы** и выберите файлы;
    - нажмите **+ вставить из буфера** и вставьте текст файла.

    Под полем появится проверка. В ней видно, какие параметры будут записаны.
5. Нажмите кнопку **Применить**. Окно закроется, а параметры появятся в разделе **Конфигурация**.

::: note
Если в репозитории несколько приложений, агент сделает отдельный файл для каждого контейнера и первой строкой файла укажет его адрес (например, `# archmap-node: Маркетплейс «Ярмарка» / Заказы / Order API`). Параметры из файла без такой строки попадут к контейнеру, со страницы которого открыто окно. Если адрес ведёт к системе или компоненту, проверка предупредит об этом.
:::

::: note
По умолчанию параметры, которые уже описаны, не меняются, и агент только добавляет новые. Чтобы параметры с теми же именами заменились описаниями из файлов, перед применением установите флажок **Заменять уже описанное**. Остальные параметры сохранятся при любой настройке.
:::

::: note
Конфигурацию удобнее описать до схем логики: тогда агент, описывая логику, сошлётся на уже известные имена параметров (см. [Документировать систему с помощью ИИ-агента](agent-docs.md#order)).
:::

<!--@include: ../_shared/agent-remarks.md-->

::: note
Описать конфигурацию может и агент, подключённый по MCP. Попросите его об этом своими словами (например, «Опиши конфигурацию Order API в проекте «Ярмарка» по этому репозиторию»). Агент покажет план и после вашего подтверждения запишет параметры в проект (см. [Подключить своего агента через MCP-сервер](mcp.md)).
:::

## Собрать конфигурацию с компонентов {#collect}

::: note
Если параметры оказались у компонентов (например, у «Приём событий» и «Шаги саги» вместо их контейнера «Оркестратор заказа»), соберите их в контейнер. Об этом напоминает рекомендация **Конфигурация и спецификации у компонентов** (см. [Разобрать рекомендации к схеме](alerts.md)).
:::

Чтобы собрать параметры компонентов в контейнер, выполните следующие действия:

1. На странице контейнера в разделе **Конфигурация** нажмите **Собрать с компонентов**. Откроется окно **Собрать с компонентов**.
2. Если в окне есть вопрос **Чьё описание считаем верным?**, выберите компонент, чьё описание перейдёт контейнеру, или **Оставить у компонентов**.
3. Нажмите кнопку **Собрать**. В окне появится итог: что собрано, что отброшено и что осталось у компонентов.
4. Нажмите кнопку **Закрыть**.

::: note
Если на вопрос не ответить, параметр останется у компонентов вместе с рекомендацией. Окно собирает и спецификации компонентов, поэтому та же кнопка есть в разделе **OpenAPI** (см. [Собрать спецификацию с компонентов](openapi.md#collect)).
:::

::: note
Если параметры остались у системы, на её странице в разделе **Конфигурация** нажмите **Перенести документацию** и выберите контейнер, которому они перейдут.
:::
