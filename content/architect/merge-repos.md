---
title: Объединить файлы из нескольких репозиториев в один проект
order: 8
---

::: note
Если код системы хранится в нескольких репозиториях, агент описывает каждый репозиторий отдельным файлом YAML. ArchMap объединяет такие файлы в один проект: объекты с одинаковым именем или одинаковым источником становятся одним объектом, а связи и компоненты из разных файлов собираются на нём. То, что объединение не может решить само, ArchMap спрашивает у вас.
:::

## Объединить файлы

Чтобы создать проект из нескольких файлов, выполните следующие действия:

1. Скопируйте задание в окне **Новый проект** на способе **ИИ-агент** (см. [Импортировать схему, собранную агентом из кода](import-agent.md)).
2. Запустите агента с этим заданием в каждом репозитории системы. От каждого агента сохраните файл YAML.
3. В окне **Новый проект** в блоке **Ответы агента** добавьте все файлы одним из способов:
    - перетащите файлы в окно все сразу;
    - нажмите **Выбрать файлы** и выберите несколько файлов;
    - нажмите **Вставить текст** и вставьте текст первого файла, затем снова нажмите **Вставить текст** и вставьте следующий.
4. Дождитесь проверки. Если появилась строка **Не всё сошлось идеально**, ответьте на вопросы под ней (см. [Устранить расхождения между файлами](#questions)).
5. Нажмите кнопку **Создать проект**, а затем **Открыть проект**.

::: note
Задание для всех репозиториев одно и то же: в нём заданы правила именования, по которым одинаковые объекты из разных файлов получают одинаковые имена. Не меняйте название системы между запусками.
:::

::: note
Площадки из разных файлов с одинаковым именем считаются одной площадкой (см. [Разместить объекты по площадкам](deployment.md)).
:::

## Устранить расхождения между файлами {#questions}

Чтобы устранить расхождения между файлами, выполните следующие действия:

1. Под строкой **Не всё сошлось идеально** прочитайте первый вопрос. Чтобы увидеть все вопросы списком, нажмите **Все вопросы**.
2. Если непонятно, откуда вопрос, нажмите на знак «?» у его заголовка. В подсказке написано, почему возник вопрос и что будет без ответа.
3. Выберите вариант ответа.
4. Нажмите **Дальше →**. На последнем вопросе кнопка называется **Завершить →**.
5. Когда вопросы закончатся, появится итог: **Разбор пройден** или **Осталось N вопросов без ответа**.

::: note
Ни один вопрос не обязателен: кнопка **Создать проект** активна всегда, а без ответа действует вариант с пометкой **по умолчанию**.
:::

::: note
Вопросы бывают такие:
- разные значения поля: у одного объекта в разных файлах разные описание, технология, роль, тип или статус (например, в одном файле объект отмечен системой, а в другом контейнером). Выберите правильное значение;
- связь в систему или контейнер: в одном файле у объекта описаны вложенные объекты, а в другом связь ведёт к самому объекту. Выберите вложенный объект (у контейнера это компонент), с которым на самом деле связан объект, или **Оставить на системе** (у контейнера **Оставить на контейнере**);
- объекты без связей: группа объектов никак не связана с остальной схемой. Выберите **Провести связь**, укажите, с чем связан каждый объект, и подтвердите кнопкой под списком (**Провести связь** или **Провести связи**). Чтобы оставить группу без связей, выберите **Оставить как есть**;
- похожие имена: два объекта названы почти одинаково (например, «Заказы» и «Заказ»). Выберите **Один объект**, задайте имя объединённого объекта и нажмите **Объединить** или выберите **Разные объекты**;
- разное содержимое: при импорте архивов одна и та же схема логики, спецификация, таблица, канал или параметр описаны по-разному. Выберите вариант; для схем логики есть **Добавить все**.
:::

::: note
Нестыковки, которые одним ответом не закрыть, ArchMap перечисляет под вопросами в списке **Придется подправить вручную**. Поправьте их в проекте после создания. Например, если в файле площадки указаны у компонента, они не переносятся, потому что площадки задаются контейнеру. Если они нужны, укажите их самому контейнеру (см. [Разместить объекты по площадкам](deployment.md)).
:::
