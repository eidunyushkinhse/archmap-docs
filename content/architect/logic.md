::: note
Схема логики — блок-схема в нотации Mermaid, которая по шагам описывает одну операцию сервиса или один воркер. Вид **Операция** описывает обработчик запроса или сценарий клиента, а вид **Воркер** описывает фоновую задачу. Как схемы выглядят у читателя, описано в [Просмотреть логику операции или воркера](../user/logic.md).
:::

## Создать схему

Чтобы создать схему логики, выполните следующие действия:

1. На странице сервиса в разделе **Логика** нажмите **+ Добавить** и выберите **Вручную**. Откроется окно новой схемы.
2. В поле **Имя схемы** введите название операции или воркера (например, «Создание заказа»).
3. В списке **Вид** выберите **Операция** или **Воркер**.
4. Если схема описывает эндпоинт API сервиса, в поле **Эндпоинт** укажите его метод и путь (например, `POST /orders`).
5. В поле кода напишите схему в нотации Mermaid. Справа превью обновляется на лету.
6. Нажмите кнопку **Сохранить**. Схема появится в разделе **Логика**.

::: note
Пример схемы:

```text
flowchart TD
    A["Принять состав корзины и адрес"] --> B{"Позиций не больше лимита?<br>зависит от: MAX_ITEMS_PER_ORDER"}
    B -- Нет --> E["422: слишком много позиций"]
    B -- Да --> C["Сохранить заказ со статусом «новый»<br>пишет: orders, order_items"]
    C --> D["Опубликовать событие «заказ создан»<br>публикует: orders.events"]
    D --> F["201: номер заказа"]
```
:::

::: note
Эндпоинт связывает схему со спецификацией OpenAPI сервиса: читатель найдёт схему по эндпоинту, а в разделе **Логика** эндпоинт виден рядом с названием схемы (см. [Добавить спецификацию OpenAPI сервиса](openapi.md)).
:::

::: note
Имя схемы должно быть уникальным в пределах объекта.
:::

## Изменить или удалить схему

Чтобы изменить схему, выполните следующие действия:

1. На странице сервиса в разделе **Логика** нажмите на схему. Откроется окно схемы.
2. В шапке окна нажмите **Изменить** и выберите **Вручную**.
3. Поправьте поля или код схемы.
4. Нажмите кнопку **Сохранить**.

::: note
Чтобы удалить схему, в режиме правки нажмите **Удалить схему** внизу окна и подтвердите удаление. Кнопка **Отмена** выходит из правки без сохранения.
:::

::: note
Переписать схему можно и силами агента: в меню **Изменить** выберите **Через ИИ-агента** (см. [Импортировать схемы логики, точки входа и факты от агента](docs-import.md)).
:::

## Сослаться на таблицы, каналы и параметры {#markers}

::: note
Пометка в тексте шага связывает схему с фактами: таблицей базы данных, каналом брокера или параметром конфигурации. По пометкам читатель видит строку **Обращения** под схемой, а на страницах базы данных, брокера и сервиса видно, какие схемы к ним обращаются.
:::

Чтобы добавить пометку, выполните следующие действия:

1. В коде схемы в подписи шага после текста добавьте перенос `<br>`.
2. Напишите маркер с двоеточием и имя факта:
    - `читает:` или `пишет:` и имя таблицы или колонки (например, `пишет: orders.status`);
    - `публикует:` или `потребляет:` и имя канала (например, `публикует: orders.events`);
    - `зависит от:` и имя параметра конфигурации этого же сервиса (например, `зависит от: MAX_ITEMS_PER_ORDER`).
3. Сохраните схему. В строке **Обращения** под схемой появится обращение: с галочкой, если факт найден, или с предупреждением, если нет.

::: note
Несколько имён перечисляются через запятую: `пишет: orders, order_items`. Если шаг и читает, и пишет таблицу, используйте слитный маркер `читает/пишет: orders`.
:::

::: note
Если таблица или канал с таким именем есть в нескольких базах данных или брокерах, укажите объект перед именем через косую черту: `пишет: БД заказов / orders`. Параметр ищется только у самого сервиса, поэтому для `зависит от:` объект не указывается.
:::

::: note
Пометка обещает факт: имя должно совпадать с таблицей, каналом или параметром, описанными в проекте (см. [Описать структуру БД, каналы брокера и параметры конфигурации](facts.md)). Пометка, для которой факт не найден, попадает в **Рекомендации** (см. [Разобрать рекомендации к схеме](alerts.md)). Если двоеточие стоит в обычном тексте (например, «зависит от: нагрузки»), уберите его.
:::
